# 命令検索CLI (search:command) 仕様

なでしこ3に用意されている命令（`doc/command_list.json`）を、ターミナルやAIエージェントから
手軽に検索するためのコマンドラインツールの仕様です。（[Issue #2385](https://github.com/kujirahand/nadesiko3/issues/2385)）

検索処理の本体は、なでしこ3自身（`batch/search_command.nako3`）で記述します。

## 目的

- 人間が「こんな命令あったかな？」とターミナルからすぐ調べられるようにする
- AIエージェントが、コード生成の前に必要な命令だけを取得できるようにする
  （[Issue #2377](https://github.com/kujirahand/nadesiko3/issues/2377) のAIコード生成ガイドから参照する）

## 使い方

```sh
# 命令名・読み方・説明から部分一致検索
npm run search:command -- ファイル

# Node.js版で使える命令だけを検索
npm run search:command -- ファイル --target cnako

# ブラウザ版の基本プラグインだけを検索
npm run search:command -- DOM --target wnako --group basic

# JSON形式で出力(AIや別ツール向け)
npm run search:command -- CSV --json

# 使い方を表示
npm run search:command -- --help
```

npmスクリプトを使わずに、直接実行することもできます。

```sh
node batch/search_command.mjs ファイル --target cnako
```

## コマンドライン仕様

### 書式

```
search_command [検索語...] [オプション]
```

- 検索語は複数指定できます。複数指定した場合はAND条件（すべてを含む命令だけ）になります。
- 検索語を1つも指定せず、絞り込みオプションだけを指定した場合は、その条件に合う命令をすべて対象とします。
- 検索語も絞り込みオプションも指定しない場合は、ヘルプを表示して終了コード`2`で終了します。

### オプション

| オプション | 説明 |
|---|---|
| `--target <名前>` | 実行環境で絞り込む。`cnako` / `wnako` / `phpnako` / `enako` |
| `--group <名前>` | プラグイン種別で絞り込む。`basic`(基本プラグイン) / `extra`(拡張プラグイン)。日本語の`基本プラグイン`/`拡張プラグイン`も指定可 |
| `--plugin <名前>` | プラグイン名で絞り込む（部分一致）。例: `plugin_node` |
| `--type <種類>` | 命令の種類で絞り込む。`関数` / `変数` / `定数` |
| `--limit <件数>` | 表示する最大件数（既定値は`50`）。`0`を指定すると無制限 |
| `--json` | JSON形式で出力する |
| `--help` | 使い方を表示する |

- 値を取るオプションは、`--target cnako`のほか`--target=cnako`の形式でも指定できます。
- オプションの指定が不正なとき（未知のオプション、値が必要なのに値がない、値が正しくない）は、
  エラーメッセージを表示して終了コード`2`で終了します。

### 検索の仕様

- 検索対象のフィールドは `name`（命令名）、`yomi`（読み方）、`description`（説明）の3つです。
- 部分一致で検索します。英字は大文字・小文字を区別しません。
- 検索語の前後の空白は無視します。

### 並び順

1. 命令名が検索語と完全一致するものを先頭にする
2. 次に、命令名の前方一致
3. 次に、命令名の部分一致
4. 最後に、説明・読み方だけが一致したもの

同じ優先度の中では、`doc/command_list.json`に登場する順序を保ちます。

## 出力

### 通常出力（既定）

1件につき2行で表示します。

```
[関数] ファイル読む (FILEを/FILEから)  plugin_node <cnako>
    ファイルFILEを読む
```

- 1行目: `[種類] 命令名 (引数と助詞)  プラグイン名 <対象環境>`
  - 引数がないときは `()` を表示しません。
  - 対象環境は`target`をカンマ区切りで表示します。
- 2行目: 説明（インデント4文字）。説明がないときは省略します。

先頭に検索条件と件数のサマリを表示します。

```
検索: 『ファイル』 (target=cnako)
38件見つかりました。
```

`--limit`で表示を打ち切った場合は、末尾にその旨を表示します。

```
... 他 30件（すべて表示するには --limit 0 を指定してください）
```

### JSON出力（`--json`）

命令オブジェクトの配列を出力します。出力するキーは次の通りで、冗長にならないよう
`url`など検索結果として不要な項目は含めません。

```json
[
  {
    "type": "関数",
    "name": "ファイル読む",
    "args": "FILEを/FILEから",
    "yomi": "ふぁいるよむ",
    "description": "ファイルFILEを読む",
    "plugin": "plugin_node",
    "group": "拡張プラグイン",
    "target": ["cnako"]
  }
]
```

- JSON以外の文字（サマリなど）は出力しません。そのまま`JSON.parse`できます。
- 一致がない場合は空配列`[]`を出力します。

## 終了コード

| コード | 意味 |
|---|---|
| `0` | 1件以上見つかった |
| `1` | 一致する命令が0件だった（通常出力では「一致する命令は見つかりませんでした。」と表示） |
| `2` | 引数・オプションの指定が不正、または検索条件が1つも指定されなかった（`--help`の表示は`0`） |
| `3` | `doc/command_list.json`が読めない、JSONとして壊れている等の実行時エラー |

## 実装方針

### ファイル構成

| ファイル | 役割 |
|---|---|
| `batch/search_command.nako3` | 検索本体（なでしこ3で記述）。引数解析・検索・絞り込み・整形・終了コード設定 |
| `batch/search_command.mjs` | 起動用のごく短いラッパー。`src/cnako3.mjs`で上記を実行する |
| `test/node/search_command_test.mjs` | CLIのテスト |
| `doc/search_command.md` | 本ドキュメント |

`package.json`に次のスクリプトを追加します。

```json
"search:command": "node batch/search_command.mjs"
```

### なぜラッパー（.mjs）が必要か

`cnako3`は、なでしこのスクリプト名より後ろの引数も含めて、コマンドライン全体を自前の
オプション解析（`src/commander_ja.mts`）にかけます。そのため、
`node src/cnako3.mjs batch/search_command.nako3 --help` と実行すると、
検索CLIではなく**cnako3自身のヘルプ**が表示されて終了してしまいます
（`-h` `-v` `-o` など、cnako3が使う短いオプションも同様に横取りされます）。

そこで、ラッパーでは次の処理だけを行います。

1. 利用者が指定した引数（`process.argv.slice(2)`）をJSON文字列にして、
   環境変数`NAKO3_SEARCH_ARGS`に格納する
2. `src/cnako3.mjs batch/search_command.nako3` を子プロセスとして起動する
   （利用者の引数はcnako3には渡さない）
3. 子プロセスの終了コードをそのまま返す

これにより、検索CLIは`--help`を含む任意のオプションを自由に定義できます。
ラッパーは起動処理だけを担当し、検索のロジックはすべてなでしこ3側に置きます。

### なでしこ3側の処理の流れ

1. `「NAKO3_SEARCH_ARGS」の環境変数取得` で引数を受け取り、`JSONデコード`して配列にする
   （環境変数がない場合は空配列として扱う）
2. 引数を解析して、検索語の配列とオプションの辞書に分ける
3. `母艦パス`をもとに `../doc/command_list.json` を`開く`で読み込み、`JSONデコード`する
4. 絞り込み（`target` / `group` / `plugin` / `type`）→ 検索語による部分一致 → 並び替え
5. `--json`の有無で出力を切り替えて`表示`する
6. 一致0件のときは `「process.exitCode=1」をJS実行` で終了コードを設定する
   （なでしこには終了コードを指定する命令がないため、`JS実行`を利用する）

`doc/command_list.json`は`npm run build:command`で生成される成果物であり、
検索用に別のデータを持つことはしません（データの二重管理をしない）。

## テスト

`test/node/search_command_test.mjs` で、ラッパーを子プロセスとして実行して検証します。

- 検索語での部分一致検索ができ、終了コードが`0`であること
- 命令名が完全一致するものが先頭に表示されること
- 検索語を複数指定するとAND条件になること
- `--target`での絞り込みが効くこと（結果すべての`target`に指定値が含まれる）
- `--group`での絞り込みが効くこと（`basic`と`拡張プラグイン`の両方の指定を確認）
- `--plugin`と`--type`での絞り込みが効くこと
- `--option=値`の形式でも指定できること
- `--limit`で表示件数を制限できること
- 一致0件のとき、終了コードが`1`になること
- `--json`の出力が`JSON.parse`でき、期待するキーだけを持つこと
- `--json`かつ一致0件のとき、`[]`が出力され終了コードが`1`になること
- `--help`で使い方が表示され、終了コードが`0`になること
- 引数なし・未知のオプション・値なし・不正な値のとき、終了コードが`2`になること

テストは`npm run test:node`（または`npm test`）で実行されます。
`src/cnako3.mjs`が必要なので、事前に`npm run build`（または`npx tsc`）を実行してください。
